## What it is
Replying to Luke Wroblewski's "why designers still have jobs" post, the author offers his open-source unslop-ui skill as a way to get agent-built interfaces as close as possible to a real designer-made UI. The repo describes it as an agent skill that cuts AI tells from UI copy, charts and dashboards and then reports what it cut and what it left for a human to decide. Its numbered rules target patterns such as tiny uppercase "eyebrow" labels over headings, decorative "01 //" numbering, subtitles that repeat the title, captions that explain the button you are looking at, badges and pulsing "live" dots tied to no real state, decorative emojis and icons, chart titles that just name the chart type, reading instructions, legends where direct labels would do, and "Learn more →" arrows. An optional visual pass replaces hue-to-hue gradients, off-scale spacing, extra-heavy font weights and showy motion with neutral defaults. It says it won't invent numbers, touch logic or layout, or remove accessibility labels, and a per-project taste file can add bans, keep exceptions or switch rules off. In replies the author says it only removes unnecessary things and works on any UI, and that he pairs it with another design skill that guides how a good product should look.

## Implications
- **Agent-made UI has a recognisable look:** menus, settings screens and store pages generated by agents tend to carry the same tells; a subtractive pass is cheaper than redesigning.
- **Rules beat taste prompts:** a numbered list of banned patterns, with a report per rule, is easier to verify than "make it look less AI".
- **Game UI applies too:** HUDs, shop screens and onboarding cards in Unity or web builds pick up badges, emojis and redundant captions the same way.
- **Experiment:** take one agent-built screen (a settings or shop menu), read the repo's rule list, have an agent apply only the rules that fit, and compare the before and after with a few players for clarity and tap accuracy.
