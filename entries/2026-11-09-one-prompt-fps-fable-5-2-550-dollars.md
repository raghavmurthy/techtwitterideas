# A small FPS built from scratch by one model in 8 hours for about $550

## What it is
Felix Rieseberg wanted to test Claude Fable 5.2 with one-shot prompts and no human feedback. He reports that everything in the resulting first-person shooter was made from scratch by the model, including the 3D models, sounds and textures. By his numbers it took about 8 hours and roughly $550 at API pricing, using about 2.7 million output tokens and 445 million input tokens, heavily cached. His post links to a playable build. Mark Kretschmann, who posts AI and tech news from a software engineer's perspective per his X bio, shared it with the headline that game development is "solved", which the replies largely dispute.

Asked for the prompt, Rieseberg said the age of prompt engineering is basically over and shared a casual request: build a first-person shooter with insanely detailed, AAA-looking quality, but small in scope, like a tiny level. He also said his project instructions file was empty. In another reply, someone else reported a similar one-line ask for a life sim that ran about 4 hours without follow-ups and was "not AAA, but it plays".

The replies split. Some found it smooth and impressive for the asset quality. Others said it looks dated, that the reload mechanics and game feel are weak, that it gets repetitive, and that the source code wasn't shared. One reply warns that the model used many more thinking tokens than an older model on the same tasks, so cost needs watching.

## Implications
- **Small scope is the trick:** the request asked for one tiny level with high visual quality, not a full game. That framing is a useful pattern for prototypes: narrow the content, raise the quality bar.
- **Procedural assets are now viable for prototypes:** models, textures and sounds were generated by the model as code rather than imported. For low-poly or stylised mobile work, that is a fast way to block out a level before real assets exist.
- **Game feel is still the human part:** the strongest criticism is about reloads, pacing and repetition, the things playtesting tunes. Budget human time there rather than on first-pass content.
- **Cost and compression:** at roughly 445M input tokens, caching mattered. Generated geometry and textures also need a pass for poly count and texture size before they would fit a mobile budget.
- **Experiment:** give an agent a one-paragraph brief for a single small scene in your style (one room or one level, a fixed triangle and texture budget, from-scratch assets), cap spend at a set amount, and let it run unattended. Then measure triangle count, draw calls and frame rate on a mid-range phone, and list which parts you'd keep, rework or throw away.
